# Research: verify-adhoc-diff

## Practices
- git scope: `git status --porcelain=v1 -z` (script-stable; `??` = untracked); `git diff HEAD` covers staged + unstaged but NOT untracked → add `git ls-files --others --exclude-standard -z`; ranges: `A..B` = direct tree compare, `A...B` = since merge-base (PR-style) | candidate: the git branch of scope detection
- svn scope: `svn diff` (WC vs BASE), `-r N:M`, `-c M`; changed list `svn diff --summarize [--xml]` / `svn status [--xml]` (`?` unversioned, `X` external, `!` missing); WC root via `svn info --show-item=wc-root` (1.9+; trim trailing whitespace on 1.9.0–1.9.4) — since 1.7 `.svn` exists only at the WC root; pitfalls: externals not descended by `svn diff`, binary files print "Cannot display", unversioned files appear only in `svn status` | candidate: the svn branch; exit code of `svn info` outside a WC not documented — test locally
- Changed file → tests: jest `--findRelatedTests <files>` (static dependency graph), vitest `related <files> --run` (static imports only); pytest has no built-in (pytest-testmon over-selects; pytest-picked re-runs changed test files only) → naming convention `test_*.py` / `*_test.py`; Maven surefire naming `*Test.java` etc. + `-Dtest=Class#method` + `-pl <mod> -amd`; Gradle `--tests 'pkg.Class'`; build-graph selection for JVM is commercial (Develocity PTS) | candidate: runner-native selection where it exists, naming convention elsewhere
Key references: https://git-scm.com/docs/git-status · https://git-scm.com/docs/git-diff · https://svnbook.red-bean.com/en/1.8/svn.ref.svn.c.diff.html · https://svnbook.red-bean.com/en/1.8/svn.ref.svn.c.status.html · https://subversion.apache.org/docs/release-notes/1.7.html · https://subversion.apache.org/docs/release-notes/1.9.html#svn-info-item · https://jestjs.io/docs/cli · https://vitest.dev/guide/cli · https://docs.pytest.org/en/stable/explanation/goodpractices.html · https://maven.apache.org/surefire/maven-surefire-plugin/examples/single-test.html · https://docs.gradle.org/current/userguide/java_testing.html

## Constraints
- spec-verifier's startup reads are change-bound — proposal.md (or loop.md) `verify:` clauses are its Completeness checklist, index.md anchors Coherence, `git diff` is "scoped to the change" (spec-verifier.md:35-42) | without a change dir the checklist is undefined and a weak model improvises one
- Completeness needs an intent anchor independent of the code: using the diff as both claim and evidence is the circular-proof pattern Anti-Cheating #5 bans | with no intent source (user words / commit messages), only Correctness + regression are assessable and the report must say Completeness was not assessed
- Home for the record: a new dir under spec/changes/ without proposal/fix/loop/quick counts as an active change (check-gate.sh:33-41, all twins) and trips the multi-active block on propose/apply; a dated dir under fixes/ without fix.md un-exempts the whole fixes tree | the ad-hoc ledger + screens must live outside spec/changes/ (or be a real fix entry)
- VCS: core knows git only (svn appears nowhere outside php-conventions prose) | svn working copies get no diff scope at all today
- Independence: verify always dispatches a fresh spec-verifier; ship already has the cheaper rule "fresh conversation audits inline, author conversation dispatches" (ship.md:20-27) | in diff mode the invoking conversation is often the one that wrote the code — inline self-audit there is the blind-spot failure the verifier exists to prevent
- Working-check order is already defined (apply.md:167-171): tests → seam mocks → live items handed over as `pending live check`, never waited on | a diff-mode run that blocks on an unstarted service violates it
- A green run proves nothing when the runner skips tests (skipTests-style config; research step 6) | runner sanity must precede trusting test results
- verify carries no UserPromptSubmit gate (gates match propose / apply / archive / ship only) and the Stop reminder targets changes with an APPROVED proposal | adding a diff mode needs no hook change, provided the record stays outside spec/changes/
- Screens capture exists in the verifier (spec-verifier.md:51: missed screens captured via browser tooling / playwright) | reusable as-is; only the target directory changes

## Decided
- [DEC-1] Diff mode triggers when /spec:verify resolves no change (no valid pointer and not exactly one active), or on explicit `--diff [range]` (both hosts; with a change present `--diff` forces diff mode) | source: R-1 | auto | the no-spec case gets a defined path instead of improvisation; the flag covers ranges and the "spec exists but I want a diff audit" case | reversibility: drop the auto-trigger, keep the flag | revised r0: auto-trigger only when ZERO active changes exist; >1 active with no pointer → list them and ask (archive.md pattern), diff mode offered as one option (reuse V-5)
- [DEC-2] Scope detection: `git rev-parse --show-toplevel` succeeds → git (changed set = `git diff HEAD` + untracked via `git ls-files --others --exclude-standard`; range → `A..B` as given) · else `svn info --show-item=wc-root` succeeds → svn (`svn status` for the changed set incl. `?`, `svn diff` / `-r N:M` for hunks; externals listed as out of scope) · neither → stop and ask for explicit paths (decided from Practices) | source: R-1 + Practices git/svn | rationale: covers untracked files on both VCSs, which plain `diff` misses | revised r0: no VCS found → scope = files this conversation edited, ask for paths only when there are none; the scope line declares that edits made outside the conversation are invisible (fidelity V-6)
- [DEC-3] Intent anchor, first hit wins: the user's words (this conversation / the command arguments) → commit messages of the range (`git log` / `svn log`) → none = diff-only; diff-only runs Correctness + regression + Reuse + charter, and the record states "Completeness not assessed — no intent source" | source: R-1 "根据上下文" + Anti-Cheating #5 | auto | the diff cannot be its own spec; declaring beats asking because every question must carry a forward exit and this one has none the user can always answer | reversibility: add an intent prompt later
- [DEC-4] Test points: changed file → related tests by runner-native selection where it exists (jest `--findRelatedTests`, vitest `related --run`), naming convention elsewhere (pytest `test_<mod>.py`, surefire `*Test.java`, Gradle `--tests`); then each touched stack's full suite once as the regression net when it runs in reasonable time; runner sanity (skipTests-style config) checked first | source: R-1/R-2 + Practices | auto | native selection is precise, conventions are the only portable fallback, the full suite catches what both miss | reversibility: scope rule is prose
- [DEC-5] Executor = ship's rule: this conversation wrote none of the diff → audits inline; it wrote any part, or cannot tell → dispatch one spec-verifier with the scope + intent lines as its checklist | source: A-3 pattern | auto | keeps "the author never audits itself" while skipping a cold dispatch when the reader is already fresh | reversibility: always-dispatch is a one-line change | revised r0: the executor rule + the no-proposal audit contract are written ONCE in skill.md § Shared Principles (independent audit) and referenced by ship.md and verify.md; spec-verifier gets one startup branch "no proposal: the brief supplies the claim list and the scope" used by both (reuse V-4)
- [DEC-6] Record = `spec/verify/<YYYY-MM-DD>-<slug>/verify.md` + `screens/` (counter suffix on collision), same ledger format plus `mode: diff`, a scope line (VCS + range + files) and an intent-source line | source: R-2 "截图证据收录" + Constraints "home for the record" | escalated | outside spec/changes/ the gates never see it; inside, it would trip the multi-active block | if wrong: a new top-level tree in every user project; undo = stop writing it, records stay as inert files | revised r0: record moves to `spec/archive/<YYYY-MM-DD>-verify-<slug>/` using ship's counter-suffix rule — no new top-level tree; /spec:view renders it by record dir (reuse V-6 + compat V-8)
- [DEC-7] UI-touching diff → the verifier's existing capture path (browser tooling, playwright fallback) into the record's screens/; an app that is not running → `pending live check` per the three-tier order, never waited on | source: R-2 + A-4/A-6 | auto | reuse, no new capture logic | reversibility: n/a | revised r0: a UI-touching diff's uncaptured screens get their own record line `screens: pending live check — <list>`, independent of the Completeness dimension (fidelity V-5)
- [DEC-8] Diff mode audits and records only — it never archives, ships, or edits fix batches; when the changed files are exactly an open fix batch's entries, it says so and recommends /spec:ship instead | source: Constraints (ship already audits batch diffs) | auto | one diff, one audit — no second "no-spec audit" path competing with ship | reversibility: n/a
